Setup guide

How to run the server engine on your own machine, from nothing installed to your first scan. No prior experience with Docker, Python or the command line assumed.

← Back to the mapper  ·  Quickstart guide

You may not need this

The tool you just came from works with no setup at all. Everything on it runs in your browser. Follow this guide only if you want the fuller results the server engine produces: certificate transparency enumeration instead of a wordlist, responses read directly instead of blocked by CORS, and specification files parsed rather than just linked.

On stripe.com, the difference looks like this:

EngineDocumentedLive hostsTo verify
Browser (the hosted page)1784
Server engine (this guide)2280

Budget about fifteen minutes, most of it waiting for Docker to install. You need a computer you can install software on, a few gigabytes of free disk space (Docker Desktop itself is most of that; the engine image is about 250 MB), and an internet connection. You do not need to know Python. You will type four commands in total, and this page gives you all four.

Step 1: Install Docker Desktop

Docker is what runs the server engine. It packages everything the engine needs so you do not have to install Python or any libraries yourself.

Download it from docker.com and run the installer, accepting the defaults. On Windows it may ask to install or update WSL and to restart your computer; let it.

Then start Docker Desktop and leave it running. This is the step people miss. Installing Docker is not enough, it has to be running. You will know it is ready when the whale icon appears in your system tray or menu bar and stops animating. The first startup can take a minute or two.

Step 2: Get the code

Go to the repository on GitHub. Click the green Code button, then Download ZIP. Save it somewhere you will find again, such as your Desktop, and unzip it. You will get a folder named API-surface-mapper-main.

If you already use Git, this does the same thing:

git clone https://github.com/tbgh011/API-surface-mapper.git

Either way, remember where that folder is. You need it in the next step.

Step 3: Open a terminal in that folder

The terminal has to be pointed at the folder you just unzipped. Opening one anywhere else and typing the command will not work, and this is the single most common thing that goes wrong.

  • Windows 11: open the folder, right-click any empty space inside it, choose Open in Terminal.
  • Windows 10: open the folder, hold Shift, right-click empty space, choose Open PowerShell window here.
  • macOS: open Terminal, type cd followed by a space, then drag the folder from Finder into the Terminal window and press Enter. That fills in the path for you.
  • Linux: most file managers offer a right-click Open in Terminal. Otherwise cd to the folder.

To check you are in the right place, type ls on macOS or Linux, or dir on Windows, and press Enter. You should see index.html, docker-compose.yml and a server folder. If you do not, you are in the wrong folder.

Step 4: Start the server engine

Type this and press Enter:

docker compose up --build

The first run takes one to three minutes and prints a lot of text. It is downloading a Python image and installing the engine's libraries. That happens once; later runs take seconds.

You will know it worked when the text stops scrolling and the last lines look like this:

api-surface-mapper  | INFO:     serving the UI from /srv/static
api-surface-mapper  | INFO:     Started server process [1]
api-surface-mapper  | INFO:     Application startup complete.
api-surface-mapper  | INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)

Leave this window open. Closing it stops the server. It will keep printing a line for every request, which is normal and is how you can watch a scan work.

Step 5: Open the tool

In your browser, go to http://localhost:8000

Use exactly that address. Do not open index.html by double-clicking it, and do not use the GitHub Pages address, because neither of those will find the engine.

You should see the familiar page with one addition under the domain box: a green SERVER ENGINE badge. That badge is your confirmation that everything is connected. If it is missing, see troubleshooting below.

Step 6: Run your first scan

Type a domain you own or are authorised to test, and press Map surface. A scan takes roughly twenty to sixty seconds depending on the size of the domain. The status strip tells you which phase is running: the public directory, then certificate transparency, then DNS resolution, then the spec probes, then response headers.

What to notice compared to the hosted page:

  • Many more live hosts, because certificate transparency lists names that actually exist rather than names someone guessed
  • The blue to verify count near zero, because the server reads the responses your browser could not
  • Green rows carrying real detail: path and operation counts, declared auth schemes, and any operations that declare no authentication

The quickstart guide explains how to read the results and what each colour means.

Stopping and starting again

To stop it, click the terminal window and press Ctrl+C. Or, from that folder:

docker compose down

To start it again another day, open a terminal in the folder as in Step 3 and run the command below. There is no --build this time, so it starts in seconds:

docker compose up

To update to a newer version later, download the repository again or run git pull, then run docker compose up --build once to rebuild.

Docker Desktop will not start

If Docker Desktop crashes on startup complaining that a .sock file cannot be accessed, it is holding orphaned socket files that Windows will not let it delete. Restarting usually does not help, because each failed start creates more of them. The fix is to move the folders aside so Docker recreates them cleanly. Quit Docker Desktop, then in PowerShell:

Get-Process -Name "Docker Desktop","com.docker.backend" -ErrorAction SilentlyContinue | Stop-Process -Force
$stamp = Get-Date -Format yyyyMMdd-HHmmss
Rename-Item "$env:LOCALAPPDATA\Docker\run" "run.stale-$stamp" -ErrorAction SilentlyContinue
Rename-Item "$env:LOCALAPPDATA\docker-secrets-engine" "docker-secrets-engine.stale-$stamp" -ErrorAction SilentlyContinue

Start Docker Desktop again. You may need to repeat this once, because a crash partway through startup can orphan a second set of files. The renamed *.stale-* folders are inert and can be deleted after your next reboot.

Port 8000 is taken

Open docker-compose.yml in any text editor and find this line:

      - "127.0.0.1:8000:8000"

Change the first number only, for example to 8001:

      - "127.0.0.1:8001:8000"

Save, run docker compose up again, and use http://localhost:8001.

A note on what you scan

Resolving a hostname and requesting a published document is ordinary, unauthenticated traffic, and that is all this does. It reads what is public and sends one GraphQL introspection query. It does not log in, guess passwords, or attempt any exploit.

That said, it makes those requests from your own machine and your own IP address, and considerably more of them than the browser version does.

Scope note. Confirm you own the domain, or that it falls inside a bug bounty program or an authorised engagement, before you scan it. If you run this somewhere other people can reach, set SCOPE_ALLOWLIST in docker-compose.yml so the instance refuses anything outside the domains you are cleared for.
